# 지문 난이도(ar_min/ar_max) 라벨링 방식 (2026-08-11)

## 배경

리딩테스트에서 같은 지문이 반복 노출되는 문제를 조사하다가, 더 근본적인 문제를 발견했다. `passages` 테이블에 레벨별로 36개씩 넣어둔 지문들의 `ar_min`/`ar_max` 라벨이 실제 지문 텍스트의 난이도와 크게 어긋나 있었다. 예를 들어 `ar_min 4.0~4.4`(AR4, 초등 4학년 안팎)로 라벨된 지문이 실제로는 "Mesoamerica", "astronomical alignment" 같은 어휘를 쓰는 대학 교재 수준 문장이었다.

레벨 선택 화면(`StepTestClient.tsx`)은 지문을 고를 때 `passages.ar_min`/`ar_max`를 그대로 신뢰하므로, 라벨이 틀리면 아이가 실제로는 훨씬 어려운(또는 쉬운) 지문을 "적정 난이도"로 받게 되고, 그 결과로 나오는 좌절/독립 판정과 AR 점수 전체가 왜곡된다. 이 문서는 라벨을 실제 텍스트 난이도에 맞춰 다시 계산한 방법을 기록한다.

## 측정 방법: Flesch-Kincaid Grade Level

별도의 외부 API 없이, 지문 텍스트만으로 계산 가능한 표준 가독성 공식인 **Flesch-Kincaid Grade Level**을 썼다.

```
FK grade = 0.39 × (전체 단어수 / 전체 문장수) + 11.8 × (전체 음절수 / 전체 단어수) − 15.59
```

- 첫 항(문장당 평균 단어수)은 **문장 구조의 복잡도**를 반영한다 — 문장이 길고 절이 많을수록 값이 커진다.
- 둘째 항(단어당 평균 음절수)은 **어휘 난이도**를 반영한다 — 다음절 단어가 많을수록 값이 커진다.
- 결과값은 대략 미국 학년 수준(grade level)에 대응한다. 이 앱의 AR 스케일도 대략 학년 수준에 대응하도록 설계되어 있어서(`AR3.0` ≈ 3학년 수준), FK grade를 AR 값의 대리 지표로 그대로 사용했다.

### 음절수 계산

Python/JS 표준 라이브러리에는 음절 카운터가 없어서, 흔히 쓰이는 정규식 기반 근사 알고리즘을 사용했다:

```python
def count_syllables(word):
    word = word.lower()
    word = re.sub(r'[^a-z]', '', word)
    if not word:
        return 0
    if len(word) <= 3:
        return 1
    word = re.sub(r'(?:[^laeiouy]es|ed|[^laeiouy]e)$', '', word)  # 묵음 e, -es, -ed 제거
    word = re.sub(r'^y', '', word)  # 어두 y는 모음 취급 안 함
    groups = re.findall(r'[aeiouy]{1,2}', word)
    return max(1, len(groups))
```

모음 그룹 수를 세되, 어말의 묵음 e(`like` → `lik` → 1음절)와 `-es`/`-ed` 굴절 어미를 먼저 제거해서 실제 발음 음절수에 가깝게 보정한다.

**한 차례 버그가 있었다**: 처음에는 어말 `e`만 제거하고 `-es`(예: `likes`, `comes`)는 처리하지 못해서, 이런 단어들이 실제보다 1음절 많게 계산됐다. 짧은 지문(문장 2~3개)에서는 이 오차가 전체 평균에 크게 영향을 줘서 일부 쉬운 지문이 실제보다 높은 등급으로 잘못 계산되는 원인이 됐다. 위 코드가 수정된 최종 버전이다.

## ar_min / ar_max 산출 공식

```
center = max(0.5, round(min(FK grade, 단어수 / 15), 1))
ar_min = max(0.1, round(center − 0.2, 1))
ar_max = round(center + 0.2, 1)
```

- **밴드 폭 ±0.2**: 기존 지문들이 대체로 0.4 폭의 좁은 밴드로 되어 있던 패턴을 그대로 따랐다. (레벨 선택 시 `선택 레벨 ± 0.5` 범위와 겹치는 지문을 후보로 삼는 쿼리와 맞물려서, 폭이 너무 넓으면 후보 풀이 과도하게 섞이고 너무 좁으면 후보가 고갈된다.)
- **하한 0.5**: `calculateFinalAR`이 최종 점수를 `[0.5, 5.0]`으로 클램프하는 것과 동일한 하한을 썼다.
- **`단어수 / 15` 상한(cap)**: 아래 "짧은 지문 보정" 참고.

## 짧은 지문 보정 (단어수 기반 상한)

문장이 2~3개뿐인 아주 짧은 지문(20~35단어)은 FK 공식의 "문장당 평균 단어수" 항이 표본 부족으로 크게 흔들린다. 우연히 한 문장만 조금 길어도 평균이 확 튀는데, 이는 실제 난이도와 무관한 노이즈다. 실제로 이 문제 때문에 "Jenny plants a small seed in the brown dirt..."(29단어, 명백히 1학년 수준) 같은 지문이 `ar_min 2.6~3.0`으로 잘못 라벨링된 사례가 발견됐다. 심한 경우 28단어 지문이 `ar_min 4.3`까지 나오기도 했다(전체 180개 중 13개 사례).

이를 막기 위해 "지문 분량이 짧으면 애초에 고학년 수준 어휘·구조를 담을 물리적 공간이 없다"는 점에 착안해, `단어수 / 15`를 상한으로 같이 적용했다. FK grade가 이 상한보다 높으면 상한값을 대신 쓴다. 이 상한은 80단어 이상인 지문(이번에 새로 쓴 AR2~AR4용 72개 포함)에는 사실상 걸리지 않고, 원래 문제가 있던 20~35단어대 지문에만 유효하게 작동한다.

## 신규 지문 72개 (AR2/AR3/AR4)

기존 라벨링 검증에서 AR2~AR4 구간에 실제로 그 학년 수준에 맞는 지문이 부족하다는 게 드러나서, 아래 기준으로 새로 작성해 넣었다.

| 레벨 | 개수 | 목표 단어수 | 첫 시도 FK 평균 | 문장을 더 짧게 다시 쓴 후 FK 평균 |
|---|---|---|---|---|
| AR2.0 | 20개 | 80~120 | 3.8 | **1.1** |
| AR3.0 | 20개 | 120~150 | 7.0 | **3.8** |
| AR4.0 | 32개 | 150~180 | 10.4 | **4.9** |

첫 시도에서는 단어수만 맞추고 문장 구조는 복문 위주로 썼더니, 단어수는 맞아도 FK 등급이 목표보다 훨씬 높게 나왔다(AR3인데 FK 7, AR4인데 FK 10). 목표 학년에 맞춰 문장을 짧게 끊고(문장당 10~13단어대) 어휘를 단순화해서 다시 쓴 뒤에야 목표 등급 근처로 들어왔다. ar_min/ar_max는 이 최종 버전의 실측 FK로 계산해서 넣었다 — 목표 레벨 숫자를 그대로 박아넣지 않고, 위와 동일한 공식(밴드 폭 ±0.2, 하한 0.5)을 똑같이 적용했다.

## 알려진 제약

- **FK grade는 근사치다.** 정식 AR(Accelerated Reader) 스케일은 Renaissance사의 독자 ATOS 공식(어휘 빈도 데이터베이스 기반)을 쓰는데, 이는 상용 비공개 자료라 접근할 수 없었다. FK grade는 문장 길이·음절수만으로 계산하는 훨씬 단순한 대체 지표라, 실제 ATOS 값과는 차이가 있을 수 있다.
- **음절수 계산은 근사 알고리즘이다.** 불규칙한 영어 발음 전체를 정확히 반영하지 못한다(고유명사, 외래어 등에서 오차 가능).
- **`단어수 / 15` 상한의 계수(15)는 경험적으로 정한 값이다.** 실측 데이터로 검증된 게 아니라, 문제가 됐던 사례들을 적정 범위로 되돌리는 값을 역산해서 정했다. 추후 실사용 데이터가 쌓이면 재조정이 필요할 수 있다.
- **과거 `reading_results`에 이미 저장된 결과는 소급 재계산하지 않았다** — [ar-level-redesign-2026-08-09.md](ar-level-redesign-2026-08-09.md)와 동일한 방침. 라벨이 바뀐 건 지문(`passages`) 테이블뿐이고, 이미 완료된 테스트의 `final_ar` 점수는 그대로 유지된다.
